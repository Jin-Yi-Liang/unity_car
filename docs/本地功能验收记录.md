## 测试方式与范围

全部 4692 种组合做了图寻路检查与 C++ TCP 契约检查。TCP 契约测试使用模拟车辆回报，验证数据与协议，不能把它说成 4692 条路线全部由真实车辆实际跑过。

69 单车辆覆盖执行于 2026-10-16，采用真正团结 Linux 播放器的 `-batchmode -nographics -qa-timescale 8` 模式，运行实际场景、碰撞体、C# 控制器和 TCP 连接，没有以假车辆回报代替运动；观察程序约 402.99 秒后记录全部送达。2026-10-18 复核结果和全部 138 次停车坐标，并另用同一个播放器在**有图形、默认 1 倍速度**下完成三单。两种运行方式分别记录。

初轮覆盖测试受后台图形帧率限制而放缓，QA 参数现同步设置时间步上限与物理步长，完整覆盖采用无图形模式。日常启动不带 QA 参数，使用默认时间设置。早期未完成轮次保留在忽略目录，不计入最终通过结果。

补充检查发现 B0068 原先的直线交接路径经过相邻门卫室，已调整停靠点，并将交接线障碍检查加入生成器与独立测试。上表全部通过结果对应调整后的最终数据。

## 停靠点含义与限制

新增点为附近道路上的仿真交接位置，未实地确认真实门口与校园交通权限。到建筑外墙的距离保存在 `data/building-docks.json`，最远约 43.6 米；B0068 调整后约 41.7 米。车辆不会开进建筑视觉中心。

当前仍为独立的运动学车辆，没有车辆间避碰或生产账号权限。车辆交汇、共用停靠点时可能重叠。六视角按单屏环境验收；没有使用六台物理显示器做硬件输出验证。房屋材质细节还原和真实动力学不属于本次实现。
